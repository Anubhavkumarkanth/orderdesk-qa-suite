Orderdesk QA Suite

Open the interactive Orderdesk workspace. It uses a fixed sample customer and synthetic products; do not enter personal information.

I built a small order service and tested it at the API, database, and browser levels. The project shows how I turn requirements into checks and clear bug reports.

What I checked

  • API inputs and boundary values, including quantity limits, coupon thresholds, and invalid order changes.
  • Database rules for order totals, stock, and linked records.
  • Checkout steps in a real browser using Playwright.
  • CI that passes on the clean app and fails when a seeded defect escapes detection.

The clean run passed all 86 checks. Each seeded defect has a reproducible report with steps, expected and actual results, evidence, and the test that guards it.

What the result means

I wrote the sample app, requirements, defects, and tests. Catching all eight seeded defects shows that the suite detects those fault types. It does not show that I found bugs in software written by someone else.

The live workspace runs the sample API and checkout. It stores only the fixed sample customer, and its sample orders reset when the host restarts.
