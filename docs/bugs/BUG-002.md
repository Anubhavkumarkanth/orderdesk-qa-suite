# BUG-002: SAVE10 rejected at exactly Rs 500.00

| Field | Value |
|---|---|
| Severity | High |
| Component | API / pricing |
| Requirement | REQ-PRC-001 |
| Origin | **Seeded deliberately** (`ORDERDESK_DEFECTS=BUG-002`); not a defect in third-party software |
| Status | Fixed in the clean build; guarded by the tests below |

## Steps to reproduce
1. Reset the data.
2. `POST /api/orders` with 2 x `BND-B` (Rs 250.00 each, subtotal Rs 500.00) and `"coupon":"SAVE10"`.

## Expected
HTTP 201, discount 5000 paise, total 45000 paise (the minimum is inclusive).

## Actual
HTTP 422 `coupon minimum not met`.

## Evidence
Captured by `scripts/capture_evidence.py` from a clean build and a defective build (`docs/bugs/evidence/BUG-002.json`):

```json
{
  "clean_build": {
    "step": "POST /api/orders BND-B x 2 (Rs 500.00) coupon SAVE10",
    "http_status": 201,
    "status": "PLACED",
    "subtotal_paise": 50000,
    "discount_paise": 5000,
    "shipping_paise": 0,
    "total_paise": 45000
  },
  "defective_build": {
    "step": "POST /api/orders BND-B x 2 (Rs 500.00) coupon SAVE10",
    "http_status": 422,
    "body": {
      "detail": "coupon minimum not met"
    }
  }
}
```

## Root cause
`app/pricing.py` `discount_for`: the minimum check uses `subtotal <= minimum` instead of `subtotal < minimum` for SAVE10, so the boundary value itself fails.

## Fix and verification
Reject only when `subtotal < minimum`. Verified: the guarding test(s) fail with the defect on and pass on the clean build (see `reports/defect-matrix.md`).

Guarded by: `test_tc_prc_001_save10_minimum_subtotal_boundary`, `test_tc_prc_002_save10_at_exact_minimum_gives_free_shipping_and_correct_total` and `test_tc_prc_008_total_identity_holds_for_every_coupon_case` in `tests/api/test_pricing_boundaries.py`.

## Why this test design catches it
Customers who hit the threshold exactly lose a promised discount; tests at 499.99 / 500.00 / 500.01 exist for this reason.
