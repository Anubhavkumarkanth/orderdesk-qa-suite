# BUG-003: Shipping charged on a Rs 500.00 order after SAVE10 is applied

| Field | Value |
|---|---|
| Severity | High |
| Component | API / pricing |
| Requirement | REQ-PRC-005 |
| Origin | **Seeded deliberately** (`ORDERDESK_DEFECTS=BUG-003`); not a defect in third-party software |
| Status | Fixed in the clean build; guarded by the tests below |

## Steps to reproduce
1. Reset the data.
2. `POST /api/orders` with 2 x `BND-B` and coupon `SAVE10`.

## Expected
shipping 0, total 45000 paise (the free-shipping decision uses the pre-discount subtotal of 50000).

## Actual
shipping 4000, total 49000 paise: the customer is charged Rs 40.00 shipping they should not pay.

## Evidence
Captured by `scripts/capture_evidence.py` from a clean build and a defective build (`docs/bugs/evidence/BUG-003.json`):

```json
{
  "clean_build": {
    "step": "POST /api/orders BND-B x 2 (Rs 500.00) coupon SAVE10",
    "http_status": 201,
    "status": "PLACED",
    "subtotal_paise": 50000,
    "discount_paise": 5000,
    "shipping_paise": 0,
    "total_paise": 45000
  },
  "defective_build": {
    "step": "POST /api/orders BND-B x 2 (Rs 500.00) coupon SAVE10",
    "http_status": 201,
    "status": "PLACED",
    "subtotal_paise": 50000,
    "discount_paise": 5000,
    "shipping_paise": 4000,
    "total_paise": 49000
  }
}
```

## Root cause
`app/pricing.py` `price_order`: the shipping basis is `subtotal - discount` instead of `subtotal`.

## Fix and verification
Use the pre-discount subtotal as the basis. Verified: the guarding test(s) fail with the defect on and pass on the clean build (see `reports/defect-matrix.md`).

Guarded by: `tests/api/test_pricing_boundaries.py::test_tc_prc_002_save10_at_exact_minimum_gives_free_shipping_and_correct_total`.

## Why this test design catches it
A discount silently removing free shipping is a classic interaction defect between two individually correct rules.
