# BUG-005: A shipped order can be cancelled

| Field | Value |
|---|---|
| Severity | High |
| Component | API / state machine |
| Requirement | REQ-LIF-002 |
| Origin | **Seeded deliberately** (`ORDERDESK_DEFECTS=BUG-005`); not a defect in third-party software |
| Status | Fixed in the clean build; guarded by the tests below |

## Steps to reproduce
1. Reset the data.
2. Place an order, then `pay` and `ship` it.
3. `POST /api/orders/{id}/cancel`.

## Expected
HTTP 409 `cannot cancel an order that is SHIPPED`; status stays SHIPPED.

## Actual
HTTP 200, status `CANCELLED`, although the goods have left.

## Evidence
Captured by `scripts/capture_evidence.py` from a clean build and a defective build (`docs/bugs/evidence/BUG-005.json`):

```json
{
  "clean_build": {
    "step": "place, pay, ship, then POST /cancel",
    "http_status": 409,
    "status": null
  },
  "defective_build": {
    "step": "place, pay, ship, then POST /cancel",
    "http_status": 200,
    "status": "CANCELLED"
  }
}
```

## Root cause
`app/main.py` `transition`: `SHIPPED` is added to the allowed source states of `cancel`.

## Fix and verification
Allow `cancel` only from PLACED and PAID. Verified: the guarding test(s) fail with the defect on and pass on the clean build (see `reports/defect-matrix.md`).

Guarded by: `tests/api/test_order_lifecycle.py::test_tc_lif_003_cancel_is_only_allowed_before_shipping[SHIPPED]`, `tests/ui/test_checkout_ui.py::test_tc_ui_007_*`.

## Why this test design catches it
State-transition testing: every (state, action) pair outside the allowed set must be rejected.
