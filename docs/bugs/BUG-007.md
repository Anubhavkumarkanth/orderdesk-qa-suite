# BUG-007: Percentage discount truncated instead of rounded half up

| Field | Value |
|---|---|
| Severity | Medium |
| Component | API / pricing |
| Requirement | REQ-PRC-006 |
| Origin | **Seeded deliberately** (`ORDERDESK_DEFECTS=BUG-007`); not a defect in third-party software |
| Status | Fixed in the clean build; guarded by the tests below |

## Steps to reproduce
1. Reset the data.
2. `POST /api/orders` with `BND-B` + `BND-E` (subtotal Rs 500.05) and coupon `SAVE10`.

## Expected
discount 5001 paise (10% of 50005 = 5000.5, rounded half up), total 45004.

## Actual
discount 5000, total 45005: the customer is over-charged one paisa.

## Evidence
Captured by `scripts/capture_evidence.py` from a clean build and a defective build (`docs/bugs/evidence/BUG-007.json`):

```json
{
  "clean_build": {
    "step": "POST /api/orders BND-B + BND-E (Rs 500.05) coupon SAVE10",
    "http_status": 201,
    "status": "PLACED",
    "subtotal_paise": 50005,
    "discount_paise": 5001,
    "shipping_paise": 0,
    "total_paise": 45004
  },
  "defective_build": {
    "step": "POST /api/orders BND-B + BND-E (Rs 500.05) coupon SAVE10",
    "http_status": 201,
    "status": "PLACED",
    "subtotal_paise": 50005,
    "discount_paise": 5000,
    "shipping_paise": 0,
    "total_paise": 45005
  }
}
```

## Root cause
`app/pricing.py` `_percent_of`: integer floor division `amount * pct // 100` instead of adding 50 before dividing.

## Fix and verification
`(amount * pct + 50) // 100`. Verified: the guarding test(s) fail with the defect on and pass on the clean build (see `reports/defect-matrix.md`).

Guarded by: `tests/api/test_pricing_boundaries.py::test_tc_prc_003_percentage_discount_rounds_half_up[items1-5001]`.

## Why this test design catches it
A one-paisa error is invisible in casual checks; it needs a fixture price whose 10% lands exactly on .5 paise.
